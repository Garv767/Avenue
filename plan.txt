# SRM KTR Opportunities Platform — Full-Proof Build Plan (Dev A + Dev B)

**Stack (fixed):** Next.js (App Router, JavaScript, `src/`, alias `@/*`) · Tailwind CSS · Supabase (Postgres + Auth) · Vercel
**Team:** Dev A = Foundation (data, auth, forms, admin, deploy) · Dev B = Frontend (layout, cards, public pages, polish)
**Goal:** Placement-help site with jobs, hackathons, learning resources, a consent-based "Marquee Wall", SRM-email-only login and admin moderation.

---

## 1. Principles (why this plan does not break)

1. **One seam:** `src/lib/api.js` and `src/lib/auth.js` (Dev A writes, Dev B only calls). Signatures never change.
2. **Mock first:** Dev A ships stubs with fake data in A1, so Dev B is never blocked. Real Supabase is swapped in later (A5) behind the same functions.
3. **Strict file ownership:** nobody edits the other's files. Conflicts become impossible by design.
4. **Security in the database, not just the UI:** RLS policies and an auth trigger enforce SRM-only signup, `approved=false` on insert, admin-only approval, and wall consent.
5. **Ethics:** no scraped or forwarded private data. Wall entries appear only with `consent_given = true AND approved = true`.

## 4. Shared Contract (frozen — changes need BOTH devs' agreement)

### Database
| Table | Columns |
|---|---|
| `jobs` | id, title, company, type (`internship`\|`full-time`), apply_link, deadline (date), posted_at (default now), approved (default false) |
| `hackathons` | id, name, organizer, mode (`online`\|`offline`), register_link, deadline, posted_at, approved (default false) |
| `resources` | id, category (`DSA`\|`Web Dev`\|`AI/ML`\|…), title, link, description, approved (default false) |
| `marquee_wall` | id, student_name, company, role, batch, linkedin (optional), tips (optional), consent_given (bool), approved (default false) |

### Data layer — `src/lib/api.js`
Every function is async and returns `{ data, error }`. `data` is **always an array** (never null); `error` is `null` or a **string** (never thrown).

- `getApprovedJobs()` newest first
- `getLatestJobs(n)`
- `getApprovedHackathons()` soonest deadline first
- `getLatestHackathons(n)`
- `getApprovedResources()`
- `getApprovedWall()` → `approved = true AND consent_given = true`
- `submitJob / submitHackathon / submitResource / submitWallEntry(obj)` → always inserts `approved=false`
- Admin (A only): `getPending(table)`, `approveRow(table, id)`, `rejectRow(table, id)`

### Auth — `src/lib/auth.js`
- `useUser()` → `{ user, loading }` (user null when logged out)
- `signOut()` → Promise
- `isAdmin(user)` → boolean (compares to `NEXT_PUBLIC_ADMIN_EMAIL`)
- Only `@srmist.edu.in` emails may sign up or log in.

### Component props (B)
`<JobCard job={row} />` · `<HackathonCard hackathon={row} />` · `<ResourceCard resource={row} />` · `<WallCard entry={row} />` (whole DB row, exact column names).

### Env vars
`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_ADMIN_EMAIL`, `NEXT_PUBLIC_USE_MOCK`. Never commit `.env.local`.

### Design tokens (both follow)
Primary `indigo-600` (hover `indigo-700`) · bg `slate-50` · text `slate-900` · muted `slate-600`
Card: `bg-white rounded-xl border border-slate-200 shadow-sm p-5`
Container: `max-w-6xl mx-auto px-4 py-8` · Button: `rounded-lg px-4 py-2 font-medium`
Input: `w-full rounded-lg border border-slate-300 px-3 py-2 focus:ring-2 focus:ring-indigo-500`
Mobile-first (base = mobile, then `sm:` `md:` `lg:`). All pages are `"use client"`.

- [ ] Logged-out user cannot open `/submit` or `/wall/submit` (redirect to `/login`)
